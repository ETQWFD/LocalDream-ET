聊天式出图客户端（新 APK，独立安装）

全新 etc.github.ai.chat「ET 聊天画师」：界面像 AI 聊天一样整洁现代（默认深色），手机自身不带模型，连接电脑上已就绪的 Local Dream ET Server v1.1.2 出图，可与主 App 同时安装。

  • 右上角设置里填：服务端地址（http://电脑IP:8080）、46 位 API Key、AI/模型名，并可设置全局反推理（负面）提示语，保存即全局生效；内置“连接测试”（就绪 / 模型加载中 / 连不上，三态中文提示）。
  • 回到对话页：只输中文提示词即可文生图；也可上传图片让 AI 修图（图生图，带重绘幅度滑杆）。生成中显示真实加载态，返回几张就显示几张——服务端批量设为 6，这里就返回 6 张。
  • 点开图片可全屏查看、保存到相册、系统分享，或一键云上传到你自己的 GitHub 仓库（在设置里填 Token 与仓库）。

用法：先在电脑启动服务端并等模型下载完整、界面显示就绪；复制其服务地址 / API Key / 模型名到本 App 设置并保存即可。批量步数默认跟随服务端（设置里可单独指定）。本客户端不出图在本地，完全依赖局域网内的服务端。

功能

  • 完全离线的文生图与图生图：英文提示逐字透传，中文提示本地或可选联网增强，不强制上传。
  • SD1.5 支持 CPU 与 GPU（OpenCL），GPU 初始化失败自动回退 CPU。
  • 出图健康检测：识别碎玻璃/NaN 时自动关闭 OpenCL、用 CPU 安全参数重试一次，并记住本机 GPU 不稳定。
  • 应用内检测更新：GitHub 优先、Gitee 兜底（Gitee 镜像需配置后开通），支持断点续传。
  • 本地日志与导出诊断：右上角“日志”查看引擎/下载/转换/生成/更新/云上传。
  • 可选 GitHub/Gitee 私有云备份（PAT），图片与日志备份到你自己的私有仓库。

模型与机型兼容

模型架构支持范围
SD1.5（含 Anything 系列） arm64-v8a / armeabi-v7a / x86_64 全部 64 位安卓机（华为麒麟、联发科、Exynos、Tensor 等）CPU/GPU 可跑，无 OpenCL 回退 CPU；32 位设备支持 CPU/GPU；x86_64 模拟器可原生跑 CPU。
SDXL / DiT / 千问等大模型 QNN NPU（libdit_engine） 当前仅骁龙 Hexagon NPU（SM8650/8750 级别）。华为等无 Hexagon 的机型不支持，App 会如实锁定、不假标。

性能取决于设备，生成耗时随分辨率平方与步数增加，不承诺秒出或 4K。图片尺寸长边按内存自适应：≤6GB 512、≤10GB 640、>10GB 768（均 64 对齐），比例支持 1:1 / 2:3 / 3:4 / 4:3 / 3:2 / 9:16 / 16:9 与自定义。

修图模式

新增整图 img2img 工作台：选择已下载且本机可用的模型 → 上传整张图片（不裁剪、不分割）→ 输入中文正向/负向提示 → 调整重绘强度（0.3–0.7，默认 0.45）→ 结果写入历史，可保存到相册或云备份。

自动反推提示词（tagger）暂未内置，目前请用中文直接描述想把图改成什么样子。

更新机制与安装

  • 检测更新读取 update.json，GitHub 主通道优先，失败自动回退镜像通道。
  • 下载走前台服务并显示进度通知；断点续传校验 206/Content-Range，不盲目删 .part。
  • 安装优先 PackageInstaller，失败回退系统安装器并引导“未知来源”。

云备份与令牌

  • 登录使用个人访问令牌（PAT），不内嵌网页收账号密码。GitHub classic 令牌勾选 repo；fine-grained 令牌需 Administration + Contents 权限。
  • 建仓遇 403（fine-grained 无建仓权限）时，可用“使用已有仓库”手动绑定你已建好的私有仓库。
  • Gitee 使用私人令牌（设置 → 私人令牌，勾选 user_info / projects）。
  • GitHub 设备码登录需开发者自行注册 OAuth App 并填入 client_id；未配置时入口暂不可用。
  • “关注开发者 / 点 Star”默认勾选、可取消，失败不影响登录与上传。
  • 令牌仅存 Android 系统密钥库，不写入日志或导出文件。

帮助与日志

常见问题与错误说明见 帮助页。日志位置：App 内右上角“日志”、导出诊断；公共目录 LocalDreamET/logs/app.log，以及 engine_*.log、convert_*.log。

  • 内存不足（std::bad_alloc）：降低图片尺寸或步数后重试。
  • 8081 启动失败：模型未下载完成、转换未完成或 ABI 不匹配。
  • x86 模拟器提示：使用已内置 x86_64 引擎的版本，或换 arm64 真机。
